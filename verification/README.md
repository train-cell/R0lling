# Verification boundaries

- `verify_all_subsystems.py`: independent Python examples. No Swift code is imported, compiled or executed.
- `verify_theme_apple_meta_compliance.py`: source/config token and plist-key presence. No UI rendering, permission exercise, or hardware compliance check.
- `audit_swift_codebase.py`: heuristic text/declaration scan. Not a compiler or concurrency checker.
- `diagnose_clip_commit_rollback.py`: source-contract check for gated clip journal save and failed-save orphan cleanup. It does not execute AppState or media/storage behavior.
- `verify_assistant_chat_context.py`: source-contract check that normal assistant chat passes all journal entries to AIRouter and AIRouter applies the configured newest-entry limit; it does not execute the full AppState flow.
- `verify_ui_source_contracts.py`: source checks for duplicate `@ViewBuilder` attributes, complete `QuickAction` routing/title/symbol switches, and the Bevel reference's three-column quick-action grid (one column at accessibility text sizes); it is a narrow regression guard, not SwiftUI type-checking. It checks the Today date hero's narrow-width wrapping fallback and real date-picker reload flow, read-only historical browsing, the compact recent-reading HealthKit preview, actual glasses status, simulation-safe glasses capture, the selectable sleep-vitals chart and empty/gap states, stage-query failure disclosure, reviewable nutrition values, stale-estimate invalidation, explicit meal save, analysis timestamp retention, and utterance-owned podcast completions. It also requires every share carousel page to keep a visible raised surface and card-based accessibility label, adjacent overview variants to keep the same readings, and Stress to remain selectable with an honest empty state.
- `obsidian_vault_no_follow_probe.swift`: compiles the production descriptor-relative vault file helper and deterministically swaps parent directories for symlinks during generated writes, attachment copies, and atomic replacement. It does not exercise the full bridge or Apple coordination/File Provider behavior.
- `ai_request_size_probe.swift`: compiles the production bounded HTTP client, chat builder, outbound PII redactor, Direct connector, and Hermes connector with narrow journal/endpoint shims under Swift 6 strict concurrency; checks normal payload serialization, early oversized-context rejection, JSON upper-bound rejection, and pre-network body rejection. It does not test a live provider, Apple networking, or rendered UI.
- `run_ai_request_xctests.sh`: builds a temporary SwiftPM package from the production AI HTTP/builder/connectors/redactor and the repository's `AIHTTPClientTests` / `OpenAIChatRequestBuilderTests`. All 15 tests passed in the latest Linux harness, including redaction across provider-bound text and vision prompt fields, valid/invalid IBAN checksum cases, preservation of non-Luhn number strings, and retention of the encoded image payload. It uses small `JournalEntry`, `AIRouter`, and endpoint-validator shims, so the two router-helper assertions do not execute the production router; it does not replace the full package or live-provider test.
- `run_journal_storage_xctests.sh`: builds the actual production journal model, storage protocol, bounded regular-file reader, file-protection wrapper, JSON storage, and repository journal-storage tests in an isolated SwiftPM package. It covers oversized journal reads and writes as well as restart, atomic update/append, date grouping, search, and legacy protocol compatibility. It does not replace the full Apple test target or iOS Data Protection validation.
- `run_ai_router_cancellation_tests.sh`: builds the actual production `AIRouter`, request builder, HTTP client, and repository router tests with narrow provider/Keychain/ImageIO shims. It checks cancellation propagation and local recall source stability; it does not exercise a live provider or AppState wiring.
- `run_voice_command_tests.sh`: builds the production `VoiceCommandParser`/utterance resolver and repository parser XCTest suite in isolation. All 14 tests pass for Greek/English commands, false clip triggers, final dictation delivery, and command deduplication; it does not exercise microphone capture or Apple Speech runtime.
- `run_highlight_reel_commit_tests.sh`: builds the production journal models, storage, mutation gate, journal committer, and saved-media URL finalizer with the repository's regression tests. All 4 tests pass, including persistent attachment discoverability and verification that cleanup is requested when viewer-URL resolution fails; the fake storage does not verify real filesystem deletion. It does not exercise AVFoundation muxing, AppState/SwiftUI, or video playback.
- `run_meal_nutrition_tests.sh`: builds the production OCR nutrition logger with its repository XCTest cases. All 5 tests pass for Greek-token totals, rejecting generic meat labels, coffee classification, heuristic disclosure, and retention of estimate timestamps and macro totals. AppState save timing and review-card fields are checked separately by `verify_ui_source_contracts.py`; live Vision and journal storage still need Apple validation.
- `run_sleep_episode_tests.sh`: builds the production Foundation sleep episode/stage/vital aggregator with its repository XCTest cases; all 12 tests pass for primary-episode selection, cross-source stage precedence, overlap/clipping, nap exclusion, vital unit normalization, sorting, episode clipping, empty data, query-failure status versus successful-empty results, legacy Codable decoding, and preserving gaps without interpolation. It does not execute the HealthKit query or SwiftUI on Apple platforms.
- `run_speech_completion_registry_tests.sh`: builds the production utterance-to-completion registry with StrictConcurrency and its repository tests; all 3 tests pass for distinct queued completions, per-utterance cancellation, exactly-once take, and stop cleanup. It does not execute AVSpeechSynthesizer or audio output on Apple platforms.
- `run_clip_watermark_contract_probe.sh`: compiles the production watermark API with narrow model/date shims and verifies a missing source cannot produce a shareable export. The Apple-only XCTest fixture exercises actual video rendering/playability; this Linux probe does not, so watermark readiness remains false until Apple build/render validation passes.
- `run_fitness_activity_tests.sh`: builds the production Foundation Fitness snapshot/calendar model and repository tests, including the Athens date boundary and retained per-workout session details. It does not execute HealthKit queries, type-check the HealthKit workout-label switch, or render SwiftUI.
- `run_glasses_connection_cancellation_probe.sh`: compiles the real MetaGlassesAdapter, state protocol, and lifecycle types under Swift 6 strict concurrency with narrow buffer/DAT shims; it cancels an in-flight simulation connection and checks that the actor exits `.connecting`. It does not exercise a linked DAT SDK, hardware, or the full app lifecycle.
- `run_knowledge_graph_tests.sh`: builds the production Knowledge Graph engine with its repository XCTest cases; the isolated Linux run passed 2/2 tests for Unicode-safe extraction and hostile Mermaid/DOT labels, escaped controls, and one statement per triple. It does not parse exports with an installed Mermaid or Graphviz renderer or exercise the Apple Obsidian integration.
- `run_agent_memory_transaction_tests.sh`: builds the production Agent folder manager with restart/recovery tests. It injects interruption after one, two, or all three commits, verifies restart returns a complete generation, and confirms external edits are preserved. Linux shims cover Foundation security-scope methods; Apple Files-provider coordination remains device-only validation.
- `run_obsidian_watcher_tests.sh`: builds the production watcher, secure directory-tree helper, and repository XCTest cases with an injected filesystem-source seam. Its 19 tests cover debounce, cancellation/restart, recursive tree setup, dynamic nested-directory addition/removal, root/nested directory replacement by identity, stale-event rejection including a prior-generation event during replacement startup, surfaced reconciliation failure, startup rollback, unsafe paths, symlink-subtree exclusion, missing-root read/list behavior, literal backslashes in POSIX names, and descriptor-budget preflight rejection before any watcher source opens. A harness-only SHA-256 support stub is not exercised by these watcher tests. This does not exercise Darwin dispatch sources, security-scoped Files providers, file-content synchronization, or SwiftUI status rendering.
- `run_hyperlapse_tests.sh`: compiles the production GPS frame selector with a narrow CoreLocation shim and its repository XCTest cases. It covers invalid configuration/samples, increasing timestamps/frame indices, endpoint retention, route distance across filtered legs, downsampling bounds, and finite metrics. The selector does not capture GPS or produce/mux video; the feature remains not ready.
- `run_storage_guard_tests.sh`: runs the repository's bounded no-follow file-reader, media-reference mutation gate, readiness-registry, and journal-search request-gate XCTest files against the actual Foundation/POSIX production sources. It covers bounded reads, symlink/FIFO rejection, cancelled queued mutations, serialization ordering, honest disabled readiness flags, and stale-search rejection. It does not validate Darwin filesystem behavior, Apple coordination, or UI rendering.
- `run_backup_restore_xctests.sh`: compiles the production backup engine, journal/media storage, Agent folder manager, and the repository's `BackupRestoreTests.swift` in an isolated SwiftPM package. All 15 Linux-applicable tests pass, including rollback after journal/Agent failures, missing or unsafe backup media, disk-reserve preflight, ID preservation, and safe collision handling when the requested target is a directory. The harness extracts the production path guard and media error declarations; its URL security-scope and capacity shims do not validate Apple Files-provider or iOS Data Protection behavior, and the iOS-only protection assertion remains device/Apple-only.
- `run_streak_manager_tests.sh`: compiles the production scavenger-streak manager and its repository tests. The five Linux XCTest cases cover local-day expiry, restart after a missed day, best-streak retention, and explicit timezone boundaries. It does not verify app badge presentation or Apple persistence/device behavior.
- `run_vision_analysis_pipeline_tests.sh`: compiles the production local-first OCR/cloud orchestration and its repository tests. The five Linux XCTest cases cover OCR-before-cloud order, cloud preparation/provider failures preserving OCR, empty results, and cancellation. The harness does not execute Apple's Vision OCR or the app's Apple UI/device capture flow.
- `run_transcript_keyword_tagger_tests.sh`: compiles the production transcript-text cue tagger and its repository tests. Five Linux XCTest cases cover Greek/English matching, word boundaries, punctuation/phrases, deterministic ordering, and the deprecated compatibility alias. It does not analyze acoustic emotion or speech prosody.
- `run_obsidian_bridge_xctests.sh`: builds the production Obsidian bridge, descriptor-relative vault file access, Agent folder manager, and both repository Obsidian test files. All 35 Linux-applicable tests pass for export/idempotence, edit conflicts/sidecars, Canvas color values, oversized and symlinked files, interrupted Agent-memory transactions, and deterministic parent-symlink swaps. Linux shims provide pass-through file coordination, bookmark defaults, security-scope APIs, and a deterministic 64-character non-cryptographic hash; the runner does not validate Apple coordination, bookmark resolution, SHA-256 correctness, or Files-provider behavior. Its path-resolution compatibility shim models Apple's nonexistent-leaf URL resolution on Linux.
- `run_on_device_vision_probe.sh`: builds a small fake Vision module and compiles the production OCR service under Swift 6 strict concurrency; runs throw-before-callback, callback-then-throw, and normal completion to exercise the checked-continuation resume-once gate. It does not replace Apple's Vision runtime test.
- `run_portable_source_probes.sh`: compiles and runs eleven additional production-source probes for AI journal/memory/location opt-ins and safe endpoint persistence, AI request-size bounds, backup/restore and Photos staging capacity, Deep Work corrupt-state recovery, Health metric scale, DAT unavailable-hook errors, glasses primary actions, Hermes URL-credential/query rejection and cleartext endpoint policy, Knowledge Graph exports, HealthKit/journal/Fitness UI state, and Obsidian descriptor-relative symlink protection. The AI flow uses a narrow fake `ImageIO` module; the Deep Work probe extracts its production declaration from the larger mixed-platform services file. The runner uses strict-concurrency checking and temporary executables. These probes cover deterministic Linux/macOS source paths; they do not verify Apple runtime, live DAT, UI rendering, or Files-provider coordination.
- `diagnose_stage*` / `diagnose_journal_media_a01_a03.py`: archived substring/mirror diagnostics tied to earlier source shapes; retained as historical investigation aids, not current CI gates.
- `.github/workflows/swift-ci.yml`: separate macOS Swift build/tests and iOS host build. These jobs provide the actual build/test results when run for a specific revision.
- The macOS Swift job runs nineteen portable, isolated production-source XCTest harnesses (including backup/restore rollback, Obsidian bridge/path and Agent transaction coverage, local-first OCR orchestration, transcript text cues, timezone-aware streak expiry, sleep-vitals aggregation, utterance-owned speech completions, recursive Obsidian directory-watcher, Hyperlapse route-selection, and VoiceCommandParser checks), three focused probes (watermark invalid-source rejection, glasses cancellation, and fake-Vision continuation), and eleven portable source probes from `run_portable_source_probes.sh`. The latest local harness results are recorded in `docs/IMPLEMENTATION_STATUS.md`; this workflow has not run on hosted GitHub Actions for this checkout. These focused checks do not replace the full package tests or iOS visual/device checks.

A successful Python job does not establish Swift runtime behavior, feature coverage, Apple/Meta compliance, or rendered UI fidelity. Current remediation has not been executed through the Apple jobs. See `docs/FINDINGS_REMEDIATION.md`.
