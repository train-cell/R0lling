## Implemented paths

- JSON journal CRUD/search/date buckets with a 64 MiB file cap; loads use bounded no-follow regular-file reads and throw on oversized/corrupt JSON, unsupported schema, and duplicate IDs. Writes preflight serialized size before JSONEncoder allocation, verify exact encoded size before atomic replacement, and do not update the cache on failure. AppState edits, favorites, date corrections, and attachment appends run through the shared media-reference mutation gate, merge against the current row, reject missing IDs, and use storage-level update/append operations so stale UI snapshots cannot resurrect deleted entries or lose concurrent attachments. Public protocol defaults preserve source compatibility for older custom storage conformers but fail closed for atomic mutations until those conformers implement storage-level operations.
- Sandboxed media storage/viewing, safe relative paths, UUID filenames with constrained alphanumeric extensions, truthful deletion counts, and file-backed Photos/Files import so large assets are copied without loading the whole file into `Data`. Photos verifies a regular non-empty source and capacity for both staging copies plus the 50 MiB reserve before its first temporary copy. Video imports accept MP4/MOV/M4V only; the viewer checks AVFoundation playability and reports playback failures. Attachments retain a bounded source basename for viewer/accessibility display without storing an imported path. Both in-memory and file-backed imports reserve payload bytes plus the fixed free-space reserve with overflow-safe arithmetic; the capacity provider is injectable for deterministic tests. Writes and orphan cleanup reject per-type folder symlinks that resolve outside the configured media root.
- Obsidian Files picker/bookmarks, scoped access, one-way Markdown export, persisted hashes/conflict sidecars, and attachment copies that verify regular-file types and copied bytes. Agent managed reads and writes coordinate the vault on Apple platforms and use no-follow, descriptor-relative operations for the vault and `Agent/` directory, including staged replacement, rollback, and a durable transaction record for its three Markdown files. On restart, the manager finalizes a fully installed generation or restores the old generation after a partial commit; if a file matches neither recorded version, it preserves the external edit and leaves recovery data for resolution. The opened vault identity is pinned per manager, directory identity is checked, original bytes are compared with the staged backup, and concurrent target replacement/content edits are rejected before commit. Linking the vault is explicit; journal saves and edits automatically export entries while it remains linked. A date move removes the old managed block only when the previous daily note still matches its recorded hash; external edits are preserved with a conflict sidecar. Corrupt hash metadata, non-UTF-8 notes, an untrusted first-contact entry block, attachment directories, or conflicting attachment bytes fail closed to preserve user files. A daily note is revalidated under file coordination immediately before replacement; generated files and conflict sidecars use exclusive creation, preserve existing content, and reuse matching prior sidecars. Apple Files-provider coordination, replacement during the initial path open, and non-cooperating concurrent writers still need device validation.
- Backup bundle/restore with schema/count/ID and bounded-manifest validation, Files export through the system document picker, and canonical attachment paths. Bundle media must exist as regular files with the declared size before restore; copied bytes are checked, and backup creation/restoration check payload size plus the 50 MiB media reserve before each copy. Temporary bundle manifest/media and restored media directories/files receive iOS Data Protection (OS-managed protection, not app-level encryption); exported Files-provider copies remain application-level plaintext. Existing target collisions are reused only when the bytes match, otherwise the entry receives a unique media path. Media is staged before one atomic insert-if-absent journal batch; media or journal failure triggers best-effort removal of newly staged/copied files. If filesystem cleanup itself fails, an unreferenced orphan may remain. Concurrent existing IDs are never overwritten. Agent memory is staged and compensated if its separate vault write fails; rollback failure is reported and referenced media is retained.
- Direct/Hermes HTTP connectors, Keychain credentials, persisted provider/endpoint/context settings; save validates only the selected endpoint, and Settings can remove stored credentials. Provider base URLs reject URL userinfo and all query parameters; unsafe active endpoints are not persisted, and unsafe inactive endpoints are replaced with the safe default before persistence. Hermes cleartext accepts only canonical dotted-decimal IPv4 addresses in its permitted private/link-local/Tailscale ranges, `localhost`, `127.0.0.1`, `::1`, or `.local`; leading-zero and alternate numeric IPv4 forms are rejected so allowlist classification matches resolver behavior. `.local` is only a hostname syntax/mDNS convenience: resolved addresses are not checked or pinned, and a routable or spoofed answer on the current link is not prevented. Treat cleartext as safe only on a trusted link; use HTTPS or an encrypted VPN when that trust is absent. Journal location names are manually editable and are sent only with a separate opt-in. Provider response bodies are streamed with an 8 MiB per-request cap, including when `Content-Length` is absent; oversized replies are canceled and surfaced as typed provider errors; URLSession redirects are rejected so authenticated POST bodies are not replayed to another origin. Journal and Agent memory opt-ins default OFF for ordinary chat. Explicit summary/recall sends corresponding entries; recall now returns deterministic local matches with stable IDs/date labels when the provider is unavailable; the shared builder selects the newest five entries in chronological prompt order, and connectors report IDs for that same selection. Malformed successful provider bodies receive typed invalid-response errors. The builder supports four image frames.
- Direct and Hermes requests enforce a 10 MiB serialized JSON body limit. The image path also caps aggregate JPEG bytes at 7 MiB before Base64 expansion. The request builder conservatively preflights model, prompt, context, memory, and up to four image frames before interpolating message strings, estimates JSON escaping before serialization, checks the exact serialized length, and the HTTP client rejects over-limit bodies again before creating a URLSession task. The limit is across all request content, so an otherwise-valid 8 MiB JPEG can be rejected once Base64 and JSON framing are included.
- Image requests reject sources over 40 MB, downsample to at most 2048 px per side, cap the encoded JPEG at 8 MB, and omit source metadata. Assistant/game Photos pickers use file-backed imports and verify file size before loading image bytes. Media cards and the viewer now decode bounded ImageIO thumbnails instead of loading full-resolution photo files into `Data`. Assistant vision on selected Photos images and eligible real captures keeps AI/OCR output in memory. The review shows all persisted estimates, including grams and macros. Real glasses capture remains unavailable without the live DAT feed. Raw H264/synthetic buffer bytes are excluded from image keyframe snapshots; live multi-frame acquisition from DAT remains unavailable.
